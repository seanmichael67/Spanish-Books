# Spanish Books — reality check, 2026-08-23

Measured, not remembered. Every number below was pulled live on 2026-08-23
(GA4 property 390456366 / `G-WP9V5R7T9N`, Search Console `sc-domain:beibeiamigos.com`,
live HTTP + headless Chromium at 375px).

## Headline

The library works. Almost nobody uses it.

Since GA4 was wired on 2026-07-16 (38 days), the whole property recorded:

| event | count |
|---|---|
| `book_open` | **1** |
| `read_page` | 7 |
| `page_turn` | 7 |
| `word_tap` | 6 |
| `book_complete` | 0 |

For comparison, the same property over the same window: 2,362 page views,
1,729 sessions, 371 `parlami_tour_page_view`, 30 `tour_booking`.

One person opened one book in five and a half weeks — and that one reader was
probably us. The shape (1 open, 7 reads, 7 turns, 6 word taps, 0 completes) is a
single continuous session, and it matches the end-to-end QA walkthrough recorded
on 2026-07-16, the day the tag went in. Real outside readership is plausibly zero.

## Is that a measurement bug?

No. Verified by headless probe on 2026-08-23:

* `https://www.beibeiamigos.com/spanish-books/el-oso/` returns 200 and the
  `#bookFrame` iframe loads `seanmichael67.github.io/Spanish-Books/books/week-01-el-oso/`.
* The book auto-starts reading and fires `book_open`, `read_page`, `page_turn`
  to `analytics.google.com/g/collect` with `tid=G-WP9V5R7T9N`.
  (The event names ride in the batched **POST body**, not the query string —
  a query-string-only network check makes it look like only the Google Ads tag
  `AW-675155383` is receiving them. It is not; GA4 gets them too.)
* Events reach a second property, `G-MD957EPY71`, as well.

Instrumentation is healthy. The zero is real demand, not a broken tag.

## Discovery

Search Console, trailing 30 days, pages matching `spanish-book`:

* 370 impressions, **4 clicks**, CTR 1.08%, average position 14.1
* Site-wide for comparison: 7,300 impressions, 153 clicks, CTR 2.10%

The pages do rank — several sit at position 3–9 for long-tail translation
queries ("the circle in spanish", "my grandmother likes to read in spanish",
"i love playing the guitar in spanish"). They earn no clicks. Live book pages
carry a bilingual `<title>` but **no `<meta name="description">`**.

## Supply is frozen, and the backlog cannot move

* Live library: **106 books**, unchanged since 2026-07-16 (`cf81e36`).
* 172 book folders exist; 66 are unlisted. Of those 66, **0 are publishable**:
  `week-98-cantar` has 3 of 7 images, everything else is a stub.
* 6 already-published books are still missing 1 image each
  (weeks 31, 32, 34, 37, 76, 77).
* Every remaining path runs through Gemini image generation — a spend decision
  (cockpit I9), not an engineering task.
* The `weekly-spanish-book-publish` cron is **gone** from crontab (33 entries,
  none matching). `scripts/publish_next_week.py` still works; it correctly
  reports `Images: 3/7; audio complete: False` and declines to publish.

The hub page still advertises "New Books Every Week!" — untrue for five weeks.

## Compute is burning on a dead target

The Hermes job `Beibei Spanish Books Nightly Builder` (cron `35 9 * * *`,
enabled, last status ok) runs `~/.hermes/scripts/spanish_books_nightly.py`,
which writes to **`~/Projects/preschool-books`** — the superseded pipeline,
different slugs, different structure, served by nothing.

It has produced roughly one book per night, including 18+ since 2026-08-18
(latest: `week-124-animales-del-desierto`, 2026-08-22). None of it is reachable
by any reader. This is not the live repo and must not be repointed at it —
the formats are incompatible and pushing to `main` here publishes to GitHub Pages.

## Monetization: nothing was ever built

No paywall, no checkout, no price, no paid tier, no sponsor slot — in this repo,
in any of the three worktrees, or on either unmerged branch. `WHATS_MISSING.md`
is a July wishlist (Mailchimp, $100–300/mo ads), not an implementation.

The only capture that exists is the free **Book Club** Divi form on hub page 1854.
It is live and rendering, it emails `admin@beibeiamigos.com`, it stores nothing,
and it appears on the hub only — none of the 106 book pages carry it.

Signups are **unmeasurable by design**: a Divi contact form persists nothing, so
the only record is whatever landed in `admin@beibeiamigos.com`, a mailbox this
session cannot read. A 60-day search of `seanmichael67@gmail.com` finds none, but
that inbox only receives manual forwards from `admin@` — its silence is not proof.
The finding is not "zero signups." It is that a capture surface has been live for
five weeks with no store, no list and no way to know.

## What this means

At 16 users and 1 book open per month there is no audience to monetize. Any
revenue surface built today would sit in front of nobody. The site's actual
money engine — 371 tour page views and 30 tour bookings in the same window —
runs entirely without the library.

The decision this data forces is not "which revenue model." It is whether to
invest in demand for the library at all, or park it and stop the nightly spend.
